## Two ways in

<CardGrid stagger>
  <Card title="A whole shop, in one click" icon="star">
    Pick a recipe — a corner grocer, a fashion boutique, a garden centre — and StoreSeeder fills the
    store across nine resources in dependency order. Brands and categories before products, products
    and customers before orders, so nothing points at nothing.
  </Card>
  <Card title="Or one resource at a time" icon="setting">
    Twenty-one generators, each with a live preview and parameters that reach the output. Narrow a
    price range and the preview narrows with it.
  </Card>
  <Card title="Whichever store you run" icon="puzzle">
    WooCommerce and Fluent Cart ship. Every record goes through that platform's own models — not
    direct database writes — so it respects the same schema, validation and money handling as real
    data.
  </Card>
  <Card title="Removable, exactly" icon="trash">

    created and nothing that merely resembles it. No date ranges, no name matching.
  </Card>
</CardGrid>

## The preview tells the truth

<Image src={products} alt="The Products generator: parameters on the left, a live preview table on the right showing names, SKUs, types, prices, stock and status" />

Every column a parameter governs comes from the same code the run uses. That sounds obvious and it is
the part most test-data plugins get wrong: a control that moves, saves, and quietly changes nothing.

<Image src={recipes} alt="The Recipes page: three cards — Fashion boutique, Corner grocer, Home and garden — each listing what it will create per resource" />

## A recipe is a vocabulary, not a dataset

It supplies the words and numeric bands that make a grocer look like a grocer — product names, a
category tree, brand names, a price band, variation axes. The generators still build every row.

That is why a fixed seed reproduces the same store on any platform, why money stays exact, and why a
recipe cannot smuggle in a broken record: there are no records to smuggle.

## Honest about what it is

StoreSeeder writes large volumes of data directly into your store. It is a development tool: use it on
development and staging sites, and back up before a large run.

There is no analytics, no licence check and no phone-home. The only outbound requests are two optional
downloads from GitHub, each behind a consent prompt an administrator has to accept.
