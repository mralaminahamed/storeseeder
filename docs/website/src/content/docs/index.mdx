## What it does

<CardGrid stagger>
  <Card title="A whole shop from a recipe" icon="star">
    Pick a recipe and click once. StoreSeeder fills the store across nine resources in dependency
    order — brands and categories before products, products and customers before orders — sharing one
    coherent vocabulary.
  </Card>
  <Card title="Or one resource at a time" icon="setting">
    Twenty-one generators with a live preview, a batch queue, and parameters that actually change the
    output. Every declared parameter reaches the entity or the writer, or it is not declared.
  </Card>
  <Card title="Whichever store you run" icon="puzzle">
    A platform driver decides where data lands, and the same generators feed every driver. Fluent
    Cart and WooCommerce ship; one filter adds another from a separate plugin.
  </Card>
  <Card title="Removable, exactly" icon="trash">
    Every row StoreSeeder writes is recorded in its own ledger, so deleting the test data removes
    what it created and nothing that merely resembles it.
  </Card>
</CardGrid>

## Not a dataset

A recipe is a **vocabulary** — the words and numeric bands that make a grocer look like a grocer —
never a dump of records. The generators still build every row, so money stays in integer minor units,
statuses stay canonical, and a fixed seed reproduces the same store on every platform.

That is the whole design. Shipping records would bypass the layer where those guarantees live.
